# Internationalization and translation guide

This document records Clash Nyanpasu's current i18n infrastructure, translation
conventions, terminology decisions, and history. It is intended for three
audiences:

- developers adding or changing user-facing text;
- translators who only edit `messages/*.json` or `locales/*.json`;
- maintainers reviewing translation pull requests.

The historical audit baseline is `ce274b29c` (2026-11-09). Coverage below
reflects the verified locale state after the accompanying translation fixes.
The normative keys are defined by the locale files in the repository. This
document explains how to choose and align wording; it does not replace reading
each message in context.

## 1. i18n and l10n

In this repository's commit conventions:

- **i18n** covers language selection, locale-file layout, Paraglide and
  `rust-i18n` configuration, plural rules, placeholders, and generation
  workflows.
- **l10n** covers wording, word order, counters, units, and punctuation in a
  specific language.

Adding a language, integrating a locale generator, or fixing locale resolution
normally uses `feat(i18n)` or `fix(i18n)`. Aligning or polishing translations
normally uses `fix(l10n)` or `chore(l10n)`. The commit category does not itself
define copy rules, but it helps locate changes in history.

The terminology standards are the default rules for new copy. Existing
conflicts are migration debt and must not prompt unrelated global replacements
outside a translation PR. The recent replacements in `zh-tw` for `記錄`,
`還原`, `發布`, and similar terms demonstrate why every occurrence requires
review.

## 2. Runtime and file layout

### 2.1 Two independent locale bundles

| Layer             | Source files                                                | Runtime                      | Primary use                                              |
| ----------------- | ----------------------------------------------------------- | ---------------------------- | -------------------------------------------------------- |
| Frontend          | `frontend/nyanpasu/messages/{en,ja,ko,ru,zh-cn,zh-tw}.json` | Paraglide, generated by Vite | Web UI, settings pages, in-page messages                 |
| Native backend UI | `backend/tauri/locales/{en,ja,ko,ru,zh-cn,zh-tw}.json`      | `rust-i18n`                  | Tray, native dialogs, crash and startup-failure messages |

The frontend bundle is declared in
`frontend/nyanpasu/project.inlang/settings.json`, whose `baseLocale` is `en`.
Paraglide generates into `frontend/nyanpasu/src/paraglide` through the Vite
plugin during `pnpm web:build` or a development build. **Do not edit generated
files by hand.** Change `messages/*.json` and rebuild.

The backend bundle is loaded by `rust_i18n::i18n!("./locales")` in
`backend/tauri/src/lib.rs`. It is a separate bundle from the frontend locale
files: changing only the frontend will not update the tray, native dialogs, or
the crash reporter.

The backend bundle currently has 102 leaf keys per language, with all six
languages complete. The frontend has about 1,590 ordinary message keys; see
[the current audit](#8-current-audit) for missing keys.

### 2.2 Canonical locale keys

All runtime layers use lowercase keys:

| Language            | Canonical key | Accepted legacy value | Installer / BCP-47 form | Native name |
| ------------------- | ------------- | --------------------- | ----------------------- | ----------- |
| English             | `en`          | `en-US`               | `en-US`                 | English     |
| Japanese            | `ja`          | —                     | `ja-JP`                 | 日本語      |
| Korean              | `ko`          | —                     | `ko-KR`                 | 한국어      |
| Russian             | `ru`          | —                     | `ru-RU`                 | Русский     |
| Simplified Chinese  | `zh-cn`       | `zh-CN`               | `zh-CN`                 | 简体中文    |
| Traditional Chinese | `zh-tw`       | `zh-TW`               | `zh-TW`                 | 繁體中文    |

Canonical keys must match byte for byte in all of these locations:

- filenames under `backend/tauri/locales/<key>.json`;
- filenames under `frontend/nyanpasu/messages/<key>.json`;
- `locales` in `frontend/nyanpasu/project.inlang/settings.json`;
- serialized values in
  `backend/nyanpasu-config/src/application/i18n.rs`;
- the date-fns locale mapping and the crash reporter's language argument.

The backend `I18nLanguage` still accepts `en-US`, `zh-CN`, and `zh-TW`, and
configuration migration normalizes legacy values to lowercase. The installer
uses BCP-47 forms; do not treat the installer's `zh-CN` as a message filename.

### 2.3 Language selection and Chinese detection

On first launch, the backend selects a language from the system locale. The
current rules are:

- `en`, `ja`, `ko`, and `ru` match by primary language tag;
- Chinese checks the script first: `Hans` means Simplified, and `Hant` means
  Traditional;
- without a script, `TW`, `HK`, and `MO` mean Traditional;
- bare `zh`, as well as `CN`, `SG`, `MY`, and similar regions, means Simplified;
- every other case falls back to English.

Frontend `localStorage` is only a fast path for the first paint. Persisted
application settings remain authoritative: after settings load, the language
provider corrects the cached language from the backend. A mismatch may cause a
locale change without reloading the page, or a reload. Do not make the cache
authoritative merely to eliminate first-paint flicker.

### 2.4 `<html lang>`, dates, and fonts

- `<html lang>` must follow the application language rather than the build-time
  `en` value. Both a language change and initial resolution update it.
- Relative time uses date-fns locales: `en`, `ja`, `ko`, `ru`, `zh-cn`, and
  `zh-tw`.
- CJK fonts are selected by the `:lang(...)` rules in
  `frontend/nyanpasu/src/assets/styles/tailwind.css`. Adding a language
  requires a matching font stack and a missing-glyph check.
- The native crash reporter receives the application language through
  `--language`; it must not guess from the OS language again. OS region, OS UI
  language, and application language are three independent inputs.

## 3. Adding and changing copy

### 3.1 Basic workflow

1. Use the English copy as the source. First confirm that it describes the
   intended product behavior rather than translating an outdated translation.
2. Add or change the key in the same logical group in all six frontend locale
   files. Do not update only one language or append unrelated keys to the end of
   a file.
3. If the text appears in the tray, a native dialog, the startup-failure screen,
   or the crash reporter, update `backend/tauri/locales/*.json` as well.
4. Preserve placeholders, line breaks, code fragments, arrows, separators, and
   protocol names.
5. Run `pnpm web:build` to generate Paraglide output, then run the relevant type
   checks and frontend tests.
6. Check truncation, line wrapping, and missing glyphs in narrow layouts,
   dialogs, settings cards, and at least one non-English UI.

### 3.2 Placeholders and plurals

Placeholder names are defined by code and must be preserved exactly. For
example, do not change `{count}` to `{数量}` or `{name}` to `{名称}`. A
placeholder may move; if the target language needs a different word order,
rewrite the whole message rather than concatenating several keys.

Eight English messages currently use Paraglide plural messages:

- `proxies_nav_group_count`
- `proxies_folder_delete_description`
- `profile_nav_count_profiles`
- `profile_nav_count_scripts`
- `profile_nav_count_overlays`
- `profile_folder_delete_description`
- `inspect_step_fields`
- `inspect_summary_changed`

English uses `one` and `other`. Russian must use `one`, `few`, `many`, and
`other`, for example:

```json
"countPlural=one": "{count} профиль",
"countPlural=few": "{count} профиля",
"countPlural=many": "{count} профилей",
"countPlural=other": "{count} профиля"
```

Translate only the strings in `match`. Do not change `declarations`, selectors,
or selector names such as `countPlural=...`. Japanese, Korean, and Chinese
currently normally use plain strings; expand them into plural objects only when
the source message is genuinely a plural object. If English changes a
singular-only string into a count message, verify that every language remains
grammatically correct.

Russian rules in brief:

- use `one` for 1, 21, 31, and similar numbers;
- use `few` for 2–4, 22–24, and similar numbers;
- use `many` for 0, 5–20, 11–14, 25–30, and similar numbers;
- use `other` for fractions and anything not covered above.

Do not copy the English `one` and `other` forms into Russian as two identical
strings.

### 3.3 New-language checklist

When adding a language, check at least:

1. the language enum, canonical key, system detection, and legacy configuration
   migration in `backend/nyanpasu-config/src/application/i18n.rs`;
2. tray, dialog, and startup-failure text in
   `backend/tauri/locales/<key>.json`;
3. `locales` in `frontend/nyanpasu/project.inlang/settings.json`;
4. the complete key set and `language` display name in
   `frontend/nyanpasu/messages/<key>.json`;
5. the date-fns locale in `frontend/nyanpasu/src/utils/date.ts`;
6. the font stack in
   `frontend/nyanpasu/src/assets/styles/tailwind.css`;
7. the language list in `backend/tauri/tauri.conf.json` and the installer;
8. the crash reporter's language argument, render matrix, and light/dark theme
   previews.

Items 7 and 8 are easy to miss: a language appearing in the frontend does not
mean the installer and native windows support it.

Keep these points in mind when using these terms:

- Simplified Chinese **内核** and Traditional Chinese **核心** are two separate,
  established choices and must not be "unified." Simplified Chinese changed
  `核心` to `内核` in #5826; Traditional Chinese changed `內核` to `核心` in
  #5461.
- Traditional Chinese **Proxy** is an independent domain term, not another
  spelling of “代理”. However, `使用者代理 (User Agent)` is an HTTP concept and
  is outside the Proxy terminology replacement.
- Japanese **ファイル** is the Profile short label for narrow UI. Use
  **プロファイル** when the text must emphasize a profile-file type. Both forms
  currently coexist; new copy must remain consistent within one screen.
- Traditional Chinese **記錄** is the standardized frontend and backend
  translation of Logs. Older backend `日誌` strings were aligned in this change.
- Provider navigation labels are normally short: Simplified Chinese “资源”,
  Traditional Chinese “資源”, and Japanese “リソース”. Body text still uses the
  domain term from the table above.
- Russian Direct uses `Прямой режим` as a mode name and `Напрямую` as a short
  label. Do not mechanically translate every occurrence of Direct with one
  word.
- Russian still contains legacy choices such as `Поставщики` (navigation),
  `Сценарий` (Script short label), and `Режим прокси` (Routing mode). The table
  is the recommended standard; these are migration debt to clean up.

- Do not mix in Simplified characters. Recent files still contain isolated
  remnants such as `时`; search the whole file for common Simplified characters
  during review.

  `連線埠` as the standard spelling of port.
- `記錄` can cover both logs and history as a noun. When they must be
  distinguished, use `歷史記錄`; do not write `記錄與記錄`.
- `發布`, `設定`, `使用者`, `資料夾`, `網路`, and `伺服器` reflect the current
  Taiwan-oriented terminology direction.

- `ファイル` and `プロファイル` currently coexist. Prefer `ファイル` in narrow

  do not mix both on one screen.

  review the entire translation. Technical errors and abbreviations still need
  review by a Japanese native speaker.

### 4.5 Geographic labels

`regionName()` localizes ISO 3166 region codes. It uses `Intl.DisplayNames` as
the fallback, but `CN`, `HK`, `TW`, and `MO` use reviewed message keys so the
wording does not change with the browser, operating system, or ICU version.

| Code | English        | 简体中文       | 繁體中文       | 日本語           | 한국어            | Русский           |
| ---- | -------------- | -------------- | -------------- | ---------------- | ----------------- | ----------------- |
| CN   | Mainland China | 中国大陆       | 中國大陸       | 中国大陸         | 중국 본토         | Материковый Китай |
| HK   | Hong Kong SAR  | 香港特别行政区 | 香港特別行政區 | 香港特別行政区   | 홍콩 특별행정구   | Гонконг (САР)     |
| TW   | Taiwan         | 台湾           | 臺灣           | 台湾             | 대만              | Тайвань           |
| MO   | Macao SAR      | 澳门特别行政区 | 澳門特別行政區 | マカオ特別行政区 | 마카오 특별행정구 | Макао (САР)       |

Rules:

- Display every region through `regionName()`; do not call `Intl.DisplayNames`
  directly from a component. The helper keeps overrides and fallback behavior
  in one place.
- The override is product copy in the six message bundles, not GeoIP data. The
  map shapes, region codes, and location classification remain unchanged.
- When adding or changing an override, update all six messages and the locale
  test that checks every supported locale. Do not hardcode a label in a
  component.
- These four codes are the current explicit exceptions. Other region codes
  follow the runtime's localized `Intl.DisplayNames` result.
- A runtime external-config override is not implemented. If the project needs
  one, add a settings-backed adapter rather than embedding country-name
  overrides in individual views.

## 5. Per-language writing guidance

### English

- English is Paraglide's base locale and the semantic source for new
  translations. When English behavior or terminology changes, update all six
  languages.
- Use plural objects for count messages. Do not hard-code a single form such as
  `1 item` or `many items`.
- Preserve the original capitalization of product names, protocol names, units,
  and code identifiers.
- In `Logs & History`, History means traffic/runtime history, not another Logs
  bundle. Do not collapse the distinction into a repeated noun.

### Simplified Chinese

- Main terms: 内核、代理、配置、连接、限制/规则 (navigation uses “规则”)、日志、
  脚本、提供者.
- `配置` can mean Profile, a configuration file, a configuration item, or
  runtime configuration. Add a qualifier when possible: “配置文件”, “运行时配置”,
  or “配置项”.
- `日志与记录` distinguishes Logs from History. Do not replace every “记录” with
  “日志”.
- Use short terms in navigation and full terms in body text. Do not treat “资源”
  as the only translation of Provider.
- Normally keep a half-width space between Chinese and Latin letters or digits,
  for example `Proxy 设置`, `TUN 模式`, and `{count} 条连接`. Existing
  parentheses and spacing are not fully consistent; new copy should follow
  neighboring keys rather than applying a global format change.

### Traditional Chinese

- Main terms: 核心、Proxy、設定檔、連線、路由規則、記錄、指令碼、提供者.
- Navigation short labels: Proxy、設定檔、連線、記錄、路由規則、資源、設定.
- Maintain a clear boundary between `Proxy` and `代理`: use `Proxy` for the
  domain object and “使用者代理” when translating `User Agent`.
- Determine whether `記錄` means log or history from context and qualifiers:
  `應用程式記錄`, `核心記錄`, `歷史記錄`, `流量記錄`.
- `詳細資訊` is the noun “details”; `詳細` is the adjective. Do not translate
  every occurrence of `details` as “詳情”.
- Preserve proper names such as `TUN`, `URL`, `YAML`, `HTTP`, `SOCKS5`, `IPC`,
  `STUN`, and `Mihomo`. Normally keep a half-width space between `Proxy` and
  Chinese text.

### Japanese

- Use the `です・ます` style and polite requests (`してください`). Do not use
  casual or imperative forms.
- Domain terms are mostly katakana: コア、プロキシ、プロファイル/ファイル、接続、
  ルール、ログ、スクリプト、グループ、ノード.
- `件` is the general counter for countable objects; use `回` for test
  iterations, `文字` for characters, and `{count} 地域` for regions.
- Avoid carrying English articles, plural `s`, and long relative clauses
  literally into Japanese. Prefer short sentences and noun phrases in UI copy.
- Do not translate technical names such as `TUN`, `WebView`, `URL`, `YAML`, and
  `HTTP` into Japanese.
- Keep the transparent-proxy mechanism names `REDIRECT` and `TPROXY` in Latin
  letters. They are protocol and mode names, not ordinary transliterations.
- The Japanese additions for transparent proxy settings, traffic views, profile
  auto-update, and geographic labels still need review by a native speaker.

### Korean

- Use polite speech: `합니다` / `하세요`. Avoid 반말 (casual speech).
- Established loanwords: 프로바이더, 프로필, 프록시, 코어, 트래픽, 대시보드,
  스크립트, 라우팅 모드, 글로벌, 다이렉트.
- `로그` is Logs; `기록` means a record, history, or recorded data. Do not
  replace every `기록` with `로그`.
- The counter `개` attaches directly to the number, with the usual order
  “noun + number + 개”: `그룹 {count}개`, `프로필 {count}개`. Use `회` for
  occurrences and `자` for characters.
- Do not mechanically add the plural `들` or translate English articles
  literally.
- Particles after placeholders are error-prone. Existing copy uses combined
  forms such as `{name}은(는)` and `{name}을(를)`. Prefer rewriting new copy so
  it does not need a particle, for example `이름: {name}` or `{name} 선택`.
- Time units attach directly to numbers: `{minutes}분`, `{count}초`,
  `{count}일`.

### Russian

- Every count message must use a plural object with the correct case forms; do
  not use a single string.
- Common terms: ядро, прокси, профиль, соединение, правило, журнал, история,
  провайдер, режим маршрутизации, скрипт, подписка.
- `журнал` is Logs and `история` is History. The plural of `соединение` is
  `соединения` / `соединений`.
- Legacy translations such as `Сценарий`, `Поставщики`, and `Режим прокси` do
  not match the standards above. Do not spread them in new copy.
- Use `«»` for quotation marks, `…` for ellipses, and keep periods in
  abbreviations such as `сек.`, `мин.`, and `дн.`.
- Russian is currently missing 100 frontend keys, and the Russian native-speaker
  review requested by #5611 is still incomplete. File existence alone does not
  establish Russian coverage.

## 6. Counters, numbers, and units

### 6.1 Counters

| Scenario             | 简体中文           | 繁體中文             | 日本語                 | 한국어             | Русский                                        |
| -------------------- | ------------------ | -------------------- | ---------------------- | ------------------ | ---------------------------------------------- |
| Proxy groups         | `{count} 个代理组` | `{count} 個代理群組` | `{count} 件のグループ` | `그룹 {count}개`   | `{count} группа / группы / групп`              |
| Connections          | `{count} 条连接`   | `{count} 條連線`     | `接続 {count} 件`      | `연결 {count}개`   | `{count} соединение / соединения / соединений` |
| Test runs            | `{count} 次测试`   | `{count} 次測試`     | `{count} 回のテスト`   | `{count}회 테스트` | `{count} тест / теста / тестов`                |
| Characters           | `{count} 个字符`   | `{count} 個字元`     | `{count} 文字`         | `{count}자`        | `{count} символ / символа / символов`          |
| Regions              | `{count} 个地区`   | `{count} 個地區`     | `{count} 地域`         | `지역 {count}개`   | `{count} регион / региона / регионов`          |
| Retained run records | `{count} 份记录`   | `{count} 份記錄`     | `{count} 回分の実行`   | `{count}개`        | `{count} запуск / запуска / запусков`          |
| List/ranking entries | `前 {count} 项`    | `前 {count} 項`      | `上位 {count} 件`      | `상위 {count}개`   | `Топ {count}`                                  |

Notes:

- Simplified Chinese selects `个/条/项/份/次` by object type; do not use “个”
  for everything. Connections and log entries normally use “条”, list and filter
  entries use “项”, and retained history data uses “份”.
- Traditional Chinese uses `個/條/項/份/次`; connections use “條”, and list
  entries use “項”.
- Japanese normally uses `件` for abstract quantities and `回` for test runs.
  Keep a half-width space between the number and counter to match existing copy.
- Korean `개`, `회`, and `자` normally attach directly to the number. The noun
  order differs from Chinese.
- Never display the Russian slash-separated forms literally. A slash indicates
  that one declined form must be chosen based on the number.

### 6.2 Information units, rates, and time

Byte and bit amounts are formatted by code; only the displayed unit symbol is
translated. `formatBytes()` wraps `filesize` with the catalog in
`frontend/nyanpasu/src/utils/format-bytes.ts` and
`frontend/nyanpasu/src/utils/information-unit.ts`. `parseTraffic()` uses the
same catalog for chart and ranking labels. Do not call `filesize` directly from
a component.

IEC byte units:

| Unit | All other locales | Русский |
| ---- | ----------------- | ------- |
| B    | B                 | Б       |
| KiB  | KiB               | КиБ     |
| MiB  | MiB               | МиБ     |
| GiB  | GiB               | ГиБ     |
| TiB  | TiB               | ТиБ     |
| PiB  | PiB               | ПиБ     |
| EiB  | EiB               | ЭиБ     |
| ZiB  | ZiB               | ЗиБ     |
| YiB  | YiB               | ЙиБ     |

SI bit units, used when a traffic widget is configured to show bits:

| Unit | All other locales | Русский |
| ---- | ----------------- | ------- |
| bit  | bit               | бит     |
| kbit | kbit              | кбит    |
| Mbit | Mbit              | Мбит    |
| Gbit | Gbit              | Гбит    |
| Tbit | Tbit              | Тбит    |
| Pbit | Pbit              | Пбит    |
| Ebit | Ebit              | Эбит    |
| Zbit | Zbit              | Збит    |
| Ybit | Ybit              | Йбит    |

Rules:

- English, Japanese, Korean, Simplified Chinese, and Traditional Chinese keep
  the internationally standardized Latin IEC and SI symbols. Do not replace
  them with translated words in compact numeric labels.
- Russian uses the Cyrillic byte and bit symbols above. They follow the binary
  prefix terminology in the Russian Wikipedia article linked from #5655. Do not
  mix Latin `KiB` and Cyrillic `КиБ` in one Russian screen.
- Never translate the number, exponent, rate suffix `/s`, or a unit token used
  for parsing or sorting. `parseTraffic()` keeps its numeric calculation and
  localizes only the returned display symbol.
- `unit_seconds` is one of the existing localizable time keys: `s` in English,
  `秒` in Japanese, Simplified Chinese, and Traditional Chinese, `초` in Korean,
  and `сек.` in Russian.
- Time-unit examples: `min` in English, `分` in Japanese, `분` in Korean,
  `分钟` in Simplified Chinese, `分鐘` in Traditional Chinese, and `мин.` in
  Russian. Apply the same pattern to hours and days.
- Latency normally appears as `{latency} ms`; Russian uses `{latency} мс`.
  Most other languages currently keep `ms`.
- Use `%` for percentages. Do not translate it to a word next to the number.
- When adding a language, add all 18 unit keys and test the formatter. If an
  IEC bit-rate display is added later, extend the catalog with its symbols and
  tests rather than formatting it with `filesize` directly.
- Dates and relative times are generated by date-fns. Do not hand-write
  language variants of “3 days ago” in messages.

## 7. Punctuation and typography

| Language            | Preferred punctuation                                  | Notes                                                                                            |
| ------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| English             | ASCII `. , : ;`; `...` or `…` follows neighboring copy | Preserve capitalization of product names and code identifiers                                    |
| Simplified Chinese  | Full-width `，。：；`, prefer `「」`, ellipsis `…`     | Existing copy mostly uses half-width `()`; do not perform a global replacement merely to “unify” |
| Traditional Chinese | Full-width `，。：；`, prefer `「」`, ellipsis `…`     | Do not mix in Simplified characters or Mainland vocabulary                                       |
| Japanese            | `。`, `、`, `（）`, `「」`, `…`                        | Keep a half-width space between numbers and counters; do not use Chinese commas                  |
| Korean              | ASCII `. , : ;`; `“”` is acceptable for quotes         | Do not use `。` or `、`; end sentences in polite speech                                          |
| Russian             | `«»`, `…`, abbreviation periods, dashes                | Pay attention to case inflection; do not copy English word order                                 |

General rules:

- Spaces after colons, the item separator `·`, arrows `↑ ↓`, and line breaks
  (`\n`) are semantic. Do not add or remove them arbitrarily.
- When Chinese and Latin text are mixed, normally keep a half-width space
  between Chinese and Latin letters or digits. Keep this consistent within one
  screen.
- Existing files contain historical differences such as half-width vs.
  full-width parentheses and mixed `“”`/`「」`. New copy should follow adjacent
  keys; clean up existing inconsistencies separately in a copy PR with
  line-by-line review.
- Do not change commands, paths, URLs, JSON/YAML examples, or error codes during
  translation.

### Key conclusions

1. **Lowercase canonical keys are a cross-layer contract.** The backend accepts
   legacy values, but they are not valid filenames for new locale files.
2. **Simplified Chinese and Traditional Chinese must use “内核” and “核心”,
   respectively.** These are two completed historical decisions.
3. **Traditional Chinese `Proxy` is a product term, not a simple synonym for
   “代理”.**
4. **Japanese short labels are a layout requirement, not a stylistic
   preference.** In narrow spaces, prefer short terms such as `概要`,
   `ファイル`, `リソース`, and `接続`.
5. **Terminology replacements require line-by-line review.** The duplicate
   words introduced by #6251 demonstrate that global search-and-replace cannot
   replace context review.

## 10. Translation review checklist

- [ ] The key exists in all six frontend locale files, in the same location and
      logical group, with no extra or duplicate key.
- [ ] The backend key also exists in all six
      `backend/tauri/locales/*.json`; no frontend key was mistaken for a backend
      key.
- [ ] Placeholder names, counts, selectors, and plural categories are complete;
      identifiers such as `{count}` and `{name}` were not translated.
- [ ] Russian count messages use `one/few/many/other`, not copies of the English
      `one/other` forms.
- [ ] The target language uses the correct counters and number order, and unit
      symbols come from the information-unit catalog; amounts, `/s`, and
      parsing tokens were not rewritten.
- [ ] Traditional Chinese contains no Simplified characters or Mainland
      vocabulary; `核心/Proxy/設定檔/連線/記錄/指令碼` and related terms are
      consistent.
- [ ] Simplified Chinese contains no Traditional characters;
      `内核/代理/配置/日志/脚本` and related terms are consistent.
- [ ] Japanese short labels are not truncated, and `ファイル`/`プロファイル`
      and `通信量`/`トラフィック` are not mixed on one screen.
- [ ] Korean uses polite speech, particles after placeholders are grammatical,
      and number/counter order is natural.
- [ ] Russian nouns, case inflection, `«»`, abbreviations, and time units are
      natural, without literal English word order.
- [ ] Punctuation, line breaks, arrows, bullets, and code/path fragments were
      not changed accidentally.
- [ ] `pnpm web:build` generated Paraglide output, and the relevant type checks
      and frontend tests pass.
- [ ] Narrow layouts, settings cards, native dialogs, and at least one
      non-English UI were checked for wrapping, truncation, and CJK glyphs.
- [ ] No broad string replacement was performed without review, and no existing
      migration debt was expanded as a side effect.
