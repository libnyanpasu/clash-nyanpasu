# sing-box 内核接入 Roadmap

日期：2026-11-11

状态：规划中。S0 尚未开始；本路线图里的任何阶段都还没有交付。

设计：[sing-box 内核接入设计](../spec/2026-11-11-sing-box-core/design.md) 及其子设计。任务卡：[S0–S3](../spec/2026-11-11-sing-box-core/tasks.md)。

基线：`main @ 93ce63265`；sing-box `v1.14.4`。

## 1. 目标与边界

最终目标：用户可以选择 sing-box 作为内核，导入 sing-box 原生配置的 Profile，使用代理选择、测速、连接、流量、日志等日常功能，并且在应用与内核各自独立更新的情况下不会因为配置 schema 变动而无法启动。

边界：

- 不做 Clash 与 sing-box 配置之间的转换。
- sing-box 与 Clash 的内容不混用，由类型与校验保证。
- 现有 Clash 系内核的行为在每个阶段结束时都不退化。
- 任何阶段都不引入全局服务状态，不让 Tauri 依赖进入 core。

不在本路线内：移动端、OpenWrt 上的 sing-box、sing-box 的预发布通道、sing-box 的 Tailscale 等扩展能力。

## 3. 各阶段

每个阶段给出目标、交付、完成判据与主要风险。完成判据都要能机械验证。

### S0 验证假设

目标：把设计里来自读源码而没有实测的结论变成有证据的结论。

交付：

- `docs/probe/sing-box/`：设计 §8 的 V1–V16 与入站移除问题的实验记录。
- 修订后的设计，状态改为“已确认”。
- 对[选中关系方案](../spec/2026-11-11-sing-box-core/config-family.md#5-选中关系)的确认。

完成判据：每条假设有结论与证据；设计 §8 只剩 S0 无法验证的项。

风险：个别假设不成立会改动设计。影响最大的是 V5（tonic 能否以 h2c 连通 API 服务）与 V6–V8（订阅的首帧与增量语义）；这两组不成立时，控制面驱动的设计需要调整，S3 的 `sing-box-api` 与 S4 的驱动不能开始。

### S1 控制面中性化

目标：让“某功能是否可用”只有一个后端来源；去掉语义中性的名字里的 `clash`。只动 Clash 家族，行为不变。

交付：`CoreApiFeatures` 与查询；模式读写命令；命令、事件、类型、hooks 的改名；前端与托盘按能力判断。

完成判据：

- 四种 Clash 系内核下的页面可见项、托盘项、模式切换与改动前一致。
- 前端与托盘里没有为判断控制面能力而比较内核名的代码。
- 绑定是最新的；改名后的命令在两个传输上的查询 / 变更分类与 HTTP 开关没有变化。

风险：改名面大，容易与并行的前端工作冲突。缓解：改名卡保持纯机械，合并窗口尽量短。

### S2 种类隔离

目标：领域模型能表达并强制“这份内容属于哪个家族”。

交付：`ClashCore` 改名为 `CoreId`；`CoreFamily`；Profile 的 `family` 与四条校验；导入时的家族；全局转换按家族过滤；成对切换工作流。

完成判据：

- 现有应用配置与 Profiles 文档样例往返逐字节不变。
- 带 `family: sing-box` 的 Profile 能保存；与 Clash 的 Config、Transform 混用时在提交前被拒绝。
- 成对切换的测试覆盖两个方向、没有记忆、候选校验失败、提交后应用失败。

风险：内核身份改名触及约 370 处并与 core 包拆分（[拆分设计](../spec/2026-11-03-core-package-split/design.md)的 B–E 阶段）争用文件。缓解：改名卡在两个拆分阶段之间落地，开始前对齐排期。

### S3 runtime 仓

目标：core-manager 能独立管理一个 sing-box 进程。

交付：`sing-box-api` crate；两层 `CoreKind`；启动、校验、版本、JSON 配置、控制器解析；gRPC 健康探测；只重启的变更分类；日志解析；native store；服务侧桥接与线格式增量；fake-core 的参数形状；runtime 发版与主仓 pin 更新。

完成判据：

- 独立使用 core-manager，一份手写的带 API 服务的 sing-box 配置可以启动到健康、应用新配置、在校验失败时返回内核的错误输出、停止并确认死亡。
- 线格式在新旧应用与新旧服务的两个错位方向上通过测试。
- 主仓更新 pin 后 Clash 系行为无变化。

风险：Windows 上的停止（V12）与 native store 的缓存损坏识别需要真实二进制反复试。缓解：这两项单列在任务卡里，结论不明时保持保守默认（强杀回退、不触发缓存隔离）。

### S4 配置生成与接线

目标：在没有界面入口的情况下，后端能用 sing-box 跑通一个 Profile 的完整生命周期。

交付：

- `SingBoxGeneration`、支持集合、构建前的世代解析与缓存。
- pipeline 尾段按家族分派；数组元素的两个新原语；世代 1.14 的 sing-box 受管设定写入器；JSON 产物。
- `CoreId::SingBox`、内核规格与端点的映射、版本读取、服务支持性检查。
- `ApiClient` 的驱动枚举与 sing-box 驱动；连接表折叠；测速完成判定；规则的静态投影；sing-box 的能力表取值。
- geodata 模式、诊断报告等零散位置的家族分支。
- 重启耗时的测量记录。

完成判据：

- 无界面测试：选中 sing-box 内核与一个 sing-box Profile，经 `NyanpasuClient` 完成启动、选择节点、测速、读连接与流量、切换模式、改设定（触发重启）、停止。
- 每个世代的受管设定 golden 测试通过；真实二进制下“空白 Profile 加全部受管设定”没有弃用警告。
- Clash 家族的全部 golden 输出不变。
- `pnpm run lint:architecture-ledger` 与 `pnpm run lint:backend-boundaries` 通过。

风险：这是工作量最大、最容易蔓延的阶段。缓解：开始前把它拆成与 S0–S3 同粒度的任务卡；首版受管范围严格限于[设计列出的表](../spec/2026-11-11-sing-box-core/config-family.md#43-sing-box-的受管设定)，TUN 等一律留给 S7。

### S5a manifest v2

目标：内核更新受世代门控，先在 Clash 系上线。

交付：v2 清单的生成脚本与工作流步骤；updater 读 v2 并按世代选版本；“需要升级应用”的提示；升级预检；v1 生成保持不变。

完成判据：

- 用 v1 与 v2 两份等价清单，每个 Clash 系内核选出的版本与资产名相同。
- 预检失败时旧二进制仍在，返回带内核输出的错误。
- 已发布的旧应用仍能从 v1 正常更新（v1 文件的结构与内容没有变化）。

风险：清单是线上契约，发布后不能随意改。缓解：结构在本阶段评审定稿；应用对未知字段与未知内核键宽容，结构性变化只通过提升 `manifest-version` 表达。

这一阶段不依赖 sing-box，可以独立发布，并且它本身就是对 Clash 系内核的改进。

### S5b 分发 sing-box

目标：sing-box 二进制能被下载、随包、更新。

交付：清单收录 sing-box；资源准备脚本按支持的世代取随包版本；sidecar 与各平台打包；便携版；credits；支持集合的单一来源。

完成判据：

- 六个目标平台的安装包都带上 sing-box，且版本在支持的世代内。
- 应用内更新 sing-box 走通，包括预检。
- 生成脚本的测试覆盖分组、保留组数、下限、资产名与归档内路径。

风险：sing-box 的 Linux 资产有多个 libc 变体，选错会在部分发行版上起不来。缓解：在 CI 的打包环境与至少一个 musl 发行版上实测后再定。

### S6 前端与预发布

目标：用户可以在界面上完成全部 sing-box 相关操作；先在预发布通道提供。

交付：内核选择按家族分组；Profile 列表的家族标记与筛选；导入对话框的家族选择；按家族的编辑器；设置页按 `ConfigFeatures` 显示；规则页的静态来源说明；动态模式列表；弃用警告；内核管理页的世代、提示与预检失败输出；i18n。

完成判据：

- 手动走查清单全部通过：导入 sing-box Profile、切换到 sing-box、日常操作、切回 Clash、应用内更新内核。
- sing-box 下不显示任何不可用的功能入口；每个被禁用的设定都有原因说明。
- 前端测试覆盖能力为假时不发请求、两种规则来源、空模式列表。

风险：订阅生态以 Clash 为主，用户预期落差。缓解：发布说明与导入对话框里写明 sing-box 需要 sing-box 原生配置，不做转换。

## 4. 必须保持的不变量

每个阶段的评审都检查：

1. `Profiles.current` 为空，或与选中内核同家族。
2. 一个家族的内容不会被另一个家族的代码路径解释。
3. 运行配置构建器是纯函数；世代、端口、版本都由调用方解析后传入。
4. 应用不会把内核更新到它不支持的世代。
5. 不支持的操作返回明确的不支持，不返回空结果冒充成功；不支持的设定不报告为已应用。
6. Clash 系内核的线格式、持久化格式、运行配置输出在每个阶段前后一致，除非该阶段的任务卡明确声明了变更。
7. 状态先提交再触发副作用；runtime 是提交前的投票方；提交后的失败按降级报告。
