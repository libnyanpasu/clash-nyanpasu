## 热度依据

仓库没有使用埋点，以下热度来自任务推断，置信度中：

- 高：总量与上下行、进程与主机排行、出口排行（按流量计费的订阅）。
- 中：当前速率；选中一项后下钻。
- 中低：路径诊断，通常从规则页或连接页跳转进入。
- 低：地理分布；单机用户的来源与入站。

## P2 项目

### 1. 总览路径预览（TODO：等查询优化后再加）

总览排行下方放一张路径预览：每列 3 个节点，模板跟随路径页；点节点在总览内筛选，“展开”进入路径页；替换网格最后一格的两个入口按钮。

这个预览曾在本分支实现，后因成本移除：总览每次轮询都要多算一份拓扑。当时的拓扑（基于 redb 存储）先为每一行建出全部节点和边，每列 3 个的限制只作用于输出；合成库上，带预览的概览单次成本是只算排行时的 2.2–2.7 倍（S 库 7 天：109 → 241 ms；M 库 7 天：311 → 717 ms）。

现在的 tsdb 存储已经分两遍投影拓扑：先由各层的分组选出保留的节点（`topology::Projection`），存储端再用 `LabelMap` 把每行直接映射到保留节点或该层的“其他”。上面的倍数因此不再适用，加回前要重新测量。

**加回的前提**，满足其一即可：

- 在 tsdb 存储上测得带预览的概览满足下面的验收；
- 拓扑从概览的 2 s 轮询中拆出来，单独以 10 s 查询，或者只在预览进入视口时才请求。

**验收：** 带预览的概览单次耗时不超过只算排行时的 1.3 倍（用 `nyanpasu-traffic` 的 `report_allocations` 基准，加一份每列 3 个节点的请求测量）。

### 2. 规则排行卡

后端 `Dimension::Rule` 已经支持排行，前端只需在 `RANKINGS` 里加一项。

- 收益：直接回答“哪条规则命中的流量最多”，有助于调整规则。从规则页跳来时已带上 rule 筛选，配合“排行忽略自身筛选”，能看到同一 profile 下其他规则的对比。
- 待定：放在热度排序的第几位；单机用户的总览会因此多一张卡。

### 3. 时间趋势图

`TrafficReport` 没有时间序列，需要后端按桶返回序列，并新增查询与 RPC，应单独立项。竞品（Clash Party、MetaCubeXD）的历史统计页都有趋势图，见 `docs/report/2026-09-16-traffic-topology-research.md`。

### 4. 排行卡片每行的开销（tooltip 已处理，动画转 #5897）

排行行（`RankingRow`）各自挂着一个 Radix tooltip 和一组 motion 动画（新行淡入、排名变化时滑动）。总览上约 25 行，每次轮询或筛选点击都会全部重新渲染。为了量化，做了两个临时诊断版本（未提交），和基线交替运行三轮，取中位数（4 倍 CPU 降速，总览，最长帧间隔 / React 渲染时间）：

| 操作     | 基线         | 行不挂 tooltip | 行不做动画   |
| -------- | ------------ | -------------- | ------------ |
| 筛选点击 | 240 / 146 ms | 182 / 103 ms   | 150 / 96 ms  |
| 打开     | 197 / 115 ms | 193 / 100 ms   | 207 / 110 ms |
| 轮询更新 | 67 / 43 ms   | 52 / 30 ms     | 50 / 35 ms   |

测量时机器有后台负载，绝对值偏高，只有同一轮内的相对差可信。两项在轮询和筛选点击上各约占渲染时间的 30%，对打开影响不大。

两项都是有意的交互，处理方式不同：

- **tooltip**：悬停和键盘聚焦都能看到完整名称（有测试覆盖聚焦的情况）。只在首次悬停或聚焦时才挂载 tooltip 的做法不可行：挂上的瞬间元素类型会变，按钮被重新挂载，键盘焦点随之丢失。现已改为每个列表共用一个 tooltip（#5893，`@nyanpasu/ui/shared-tooltip`），交互不变。
- **动画**：排名变化时行滑到新位置，是有意加入的效果（`66f3ed64a`）。开销主要出现在筛选点击：整个列表被替换，很多行同时换位，每行都要测量布局。折中方案是筛选变化时不播滑动、只在轮询导致排名变化时播；这会改变可见效果，单独在 #5897 跟踪。

把页面切换拆成多帧渲染、以满足满速 120 Hz 的目标，同样会改变切换时的可见效果，在 #5898 跟踪。

复现：`pnpm -F @nyanpasu/nyanpasu bench traffic`，配合 `VITE_PERF_PAGES=overview`、`VITE_PERF_THROTTLE=4`；要看 CPU profile 时加 `VITE_PERF_PROFILE=<文件>`，只录轮询或切换再加 `VITE_PERF_PROFILE_ACTION=poll|switch`。比较两个版本用 `deno task bench:ab --cores performance`，固定在大核上交替运行。

已经处理的前端开销：排行的完整列表不再跟着轮询和翻页重新渲染，列表行也不做动画（`perf(traffic): keep the ranking listing out of polls and page loads`，先作用于“查看全部”对话框，随后随列表移到分类排行页）。

## 已放弃

### 筛选变更改用 `replace` 写入历史

原计划让筛选变更不再推入浏览器历史，使“返回”直接离开页面。路径页和地图页已能显示排行，不再需要回总览看结果；而且改用 `replace` 后返回总览时，路径页上选的筛选同样会丢失。收益不足以改变现有的历史行为，因此不做。
