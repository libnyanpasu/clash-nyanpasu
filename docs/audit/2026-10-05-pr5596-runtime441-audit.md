## 0. 结论摘要

1. **`/group` 对组发现没有带来新信息。** Mihomo 的 `getGroups` 与 `getProxies` 都遍历 `tunnel.Proxies()`，前者只多了“是否 ProxyGroup”的过滤；Meow 的 `get_groups` 等于 `get_proxies` 再按 `members().is_some()` 过滤。两边的记录由同一个序列化函数产生。#441 自带的真实进程测试也断言了 `listed == inferred`（`tests/proxy_cores.rs`，Mihomo 与 Meow 均成立）。issue #5112 的根因只是“把 `GLOBAL.all` 当作组全集”，修正 `from_responses` 就足够。
2. 为了“按能力请求 `/group` 并按内核选择格式”，两个 PR 引入了一整条链：`Feature::ProxyGroupList` 及版本下限 → `ApiConnection.kind/capabilities` → IPC `CoreApiConnection` 破坏性字段 → service 升到 rc.12 → 应用把 `REQUIRED_SERVICE_MIN` 提高到 rc.12，**强制所有用户升级服务**。另外还有 `GroupListFormat`、`GroupSource/GroupFallback`、诊断去重等代码。按第 1 条，这条链的收益接近零，成本却很高。
3. review 意见全部成立，且彼此一致：校验不属于传输层；空成员组不应报错；`group_list_format` 不该作为 Client 字段；`kind` 不必要。
4. **推荐方案 A：** 刷新流程不再调用 `/group`，只保留“无尾斜杠路径修正 + `from_responses` 推断算法修正”。若坚持 group 优先，可用方案 B 的精简实现。两个方案都需要用户拍板，见 §6。

## 2. 发现（按严重度排序）

### F1（高，设计）：能力和内核类型的传递链收益为零，成本是强制升级服务

- **事实：** `/group` 与“按 `all.is_some()` 过滤 `/proxies`”在 Mihomo 和 Meow 上返回同一组记录。
  - Mihomo：`hub/route/groups.go` `getGroups` 与 `hub/route/proxies.go:62` `getProxies` 都读 `tunnel.Proxies()`。
  - Meow：`routes.rs:457` 与 `:388` 都读 `route_snapshot().proxies`。
  - clash-rs 没有 `/group`，本来就只能推断。
- **成本：**
  - runtime 侧：Feature 及版本下限（`feature/clash.rs` +51 行）、manager/spec/bridge/IPC/shortcuts 的字段与夹具、两个 crate 的版本号 bump。
  - 应用侧：`compat.rs` 把 `REQUIRED_SERVICE_MIN` 改成 `2.0.0-rc.12`，rc.10/rc.11 用户必须先升级服务才能使用服务模式，只为了取得一个用不上的能力位；另外还有 `endpoint.rs` 和 `connection_policy` 夹具。
- **唯一的理论差异：** Mihomo 中某个组的 `all` 为 null 时（见 R2），会出现在 `/group` 里，却不会被推断出来。按当前源码这种情况几乎无法触发。如果确实需要覆盖，在推断端补一条按类型识别的规则即可，不需要第二个接口。
- **置信度：** 当前版本为高（源码与 PR 自带实测一致）；Mihomo 早期版本为中（未逐版核查 `EmptyFallback` 之前的返回值）。

### F2（中，正确性/健壮性）：传输层校验否决整份列表

见 R1/R2。另外，重名检查和 key/name 一致性检查在两个上游都不可能触发：Go 遍历 map 和 Rust `HashMap` 都保证键唯一，Meow 的键就取自记录名。这两项是死代码，却换来了 `GroupMap` 自定义 visitor（`proxies.rs:316-347`）、`Error::InvalidGroupList`，以及 `GroupFallback::InvalidList(&'static str)` 这条诊断分支。

### F3（中，简化）：401/403 特判是冗余的

`api.rs:198` 让 `/group` 的 401/403 向上传播，其他错误则降级为推断。但三个请求共用同一个 Client 和同一个 secret，并且一起放在 `try_join!` 里：`/group` 返回 401 时，`proxies()` 同样会返回 401，整次刷新照样失败。这个特判和对应的测试分支（`proxy_group_failures_fall_back_but_authentication_does_not` 中的 401/403 部分）都可以删除。

### F4（中，简化）：诊断状态过度设计

- `GroupSource`/`GroupFallback`（6 个变体）存进 actor `Snapshot`，只用于“来源变化时打 warn/debug 日志”和测试断言（`core/proxies.rs:160-184`）。
- `inconsistent_groups` 用 `PartialEq` 比较 `/group` 与 `/proxies` 中的同名记录（`clash/proxies.rs:117`）。两次请求并发进行，`history`、`now`、`alive` 会随测速或选择变化，所以“不一致”大多是采样时刻的竞争，信号价值低。它还迫使 `ProxyItem`、`ProxyItemHistory` 增加 `PartialEq` derive（`clash/api.rs:79,86`）。
- `unresolved_members` 只在 debug 级别输出计数。这些成员已经以 `Unknown` 节点的形式出现在结果里，可以直接观察到。
- 这三项与 `ProxyAssembly` 包装类型（`clash/proxies.rs:95`）都可以删除，`from_responses` 恢复为直接返回 `Proxies`。

### F5（低，行为变化，确认无回归）：hidden 组会进入 groups

改动后会列出不在 GLOBAL 中的组，其中包括 `hidden: true` 的组。前端 `frontend/query/src/ipc/use-clash-proxies.ts:67` 已经过滤 `!group.hidden`，因此不是回归，在此记录备查。

### F6（低，可保留）：无尾斜杠路径修正是必要且独立的

Meow 与 clash-rs 对 `/proxies/`、`/providers/proxies/` 返回 404（前序报告中的实测表），这项修正与组发现无关，应当保留。它连同 `rest.rs` 中的路径编码测试，是 #441 中唯一必须的部分。建议独立成一个提交。

### F7（低）：真实进程测试的小问题

`tests/proxy_cores.rs` 先 bind 端口再 drop，存在端口竞争；启动等待使用 20 ms 轮询。测试默认 `#[ignore]`，可以接受。若采用方案 A，其中 `groups()` 的断言可以删除，只保留“`/proxies` 推断集合正确”的断言，作为 F1 的回归证据。

### 3.2 Meow 与 Mihomo 返回结构不一致：自定义反序列化 vs 多结构尝试

两种结构在 JSON 层面互斥（数组 vs 对象），推荐**单个 visitor 同时实现 `visit_seq` 与 `visit_map`**：

```rust
// Mihomo returns `proxies` as an array, Meow as a name-indexed object.
struct GroupList(IndexMap<ProxyName, Proxy>);

impl<'de> Deserialize<'de> for GroupList {
    fn deserialize<D: Deserializer<'de>>(d: D) -> Result<Self, D::Error> {
        struct V;
        impl<'de> Visitor<'de> for V {
            type Value = IndexMap<ProxyName, Proxy>;
            fn expecting(&self, f: &mut fmt::Formatter) -> fmt::Result {
                f.write_str("a proxy group array or name-indexed object")
            }
            fn visit_seq<A: SeqAccess<'de>>(self, mut s: A) -> Result<Self::Value, A::Error> {
                let mut out = IndexMap::new();
                while let Some(p) = s.next_element::<Proxy>()? {
                    out.insert(p.name.clone(), p);
                }
                Ok(out)
            }
            fn visit_map<A: MapAccess<'de>>(self, m: A) -> Result<Self::Value, A::Error> {
                IndexMap::deserialize(MapAccessDeserializer::new(m))
            }
        }
        d.deserialize_any(V).map(GroupList)
    }
}
```

- 相比 `#[serde(untagged)] enum { List(Vec<Proxy>), Map(IndexMap<..>) }`：untagged 会先缓冲成 `Content` 再逐个尝试，出错时只给出 “did not match any variant”，丢失具体字段错误。visitor 只走一次，且保留 serde_json 的原始错误位置。
- 原设计反对“猜格式”，理由是怕掩盖协议错误。但数组和对象的判别是结构性的，不存在误判。真正的协议错误（如字段类型错误、`null`）照样会以 `Error::Decode` 的形式暴露。因此这个顾虑不适用。
- 完成后，`GroupListFormat`、Client 字段、builder 方法、应用侧的 kind 映射以及 `ApiConnection.kind` 全部可以删除（对应 R3/R4）。

### 3.3 统一用 `IndexMap` 代替 `Vec<(ProxyName, Proxy)>`：建议采纳

- `Vec<(ProxyName, Proxy)>` 存在的唯一理由，是把重复的 JSON 键保留到后续校验中检出（`proxies.rs:321` 的注释）。按 F2，两个上游都不可能产生重复键，这个理由不成立。
- 同 crate 的 `proxies()`、`proxy_providers()` 已经返回 `IndexMap` 并接受 last-wins 语义，统一后行为一致。
- 应用侧 `from_responses` 拿到列表后，第一件事就是按名字收集成 `IndexMap`（`clash/proxies.rs:108-120`）。返回 `IndexMap` 可以省去这一步。
- 外层顺序：Mihomo 的数组顺序来自 Go map 遍历，Meow 来自 `HashMap`，两者都不稳定；应用会自行排序（`clash/proxies.rs:170`）。`IndexMap` 只保留到达顺序，不承诺任何语义顺序。
- 代价：`groups()` 的签名会从 `Vec<Proxy>` 变为 `IndexMap<ProxyName, Proxy>`，属于公共 API 破坏性变更。目前唯一的调用方是 `tests/mihomo.rs:465`，迁移成本很低，符合仓库“可迁移 breaking change”的方针。
- 结论：采纳。方案 A 下应用不再调用 `groups()`，这项改动仅作为 clash-api 自身正确性修正，可选做。

## 4. 推荐方案 A：去掉 `/group`，只修推断

**runtime #441 保留：**

1. 无尾斜杠路径（`proxies.rs` 中所有 `endpoint_with_segments(..., [.., ""])` → 去掉空段），以及 `rest.rs` 的路径编码测试。
2. （可选）`groups()` 改为 §3.2 的 `GroupList` + §3.3 的 `IndexMap`，`/group/` → `/group`，并补数组/对象两种形状的解码测试。
3. `proxy_cores.rs` 只保留 `/proxies` 推断集合的断言。

**runtime #441 删除：** `Feature::ProxyGroupList` 及测试、manager/spec/bridge/IPC/shortcuts/roundtrip 中的 `kind` 与 `capabilities`、两个 crate 的 rc.12 版本 bump、`capabilities.rs` 中两条 Meow 探测测试、`fake_core.rs` 的 version-output 钩子、`GroupListFormat`、`GroupMap` 及其 visitor、`InvalidGroupList`、`tempfile` dev-dep（若 `proxy_cores` 仍需要则保留）。

> 注：两条 Meow 版本探测测试覆盖的是“Meow 因为新增版本相关能力而进入 `-v` 探测路径”这一新行为。删除能力后，该路径不再触发，测试随之失去意义。

**应用 #5596 保留：**

- `Proxies::from_responses`：按 `all.is_some()` 收集组集合，GLOBAL 只作排序提示，剩余组按名称追加，provider 补全与 Unknown 占位逻辑不变。
- 函数签名恢复为两个参数，返回 `Result<Proxies>`。
- 相应的纯函数测试：去掉 authoritative 维度，保留 GLOBAL 有/无与正反序两个维度。

**应用 #5596 删除：** `ProxySnapshot` 的 `groups/source`、`GroupSource`、`GroupFallback`、`ProxyAssembly`、`ProxyItem` 的 `PartialEq`、actor `Snapshot` 的三个诊断字段与日志逻辑、`actor_v2/api.rs` 的 `proxy_snapshot_tests` 模块（约 230 行）、`endpoint.rs`/`connection_policy.rs` 的字段补丁、`compat.rs` 的 `REQUIRED_SERVICE_MIN` 改动及其测试，以及 actor 测试中的 `/group` 路由与 `group_reads`。

> 注：`proxy_snapshot()` 可以改回二元组，或保留为只有 `proxies/providers` 的具名结构，按周边风格二选一。

**规模估计：** #441 的代码改动约 −250 行，剩下路径修正与可选的解码修正。#5596 的 Rust 改动从约 +590 行降到约 +120 行。应用不再要求服务 rc.12，submodule 只需指向含路径修正的 runtime 版本。

**风险：** Mihomo 组的 `all` 为 null 时推断不到该组（F1，当前源码不可达）。如需兜底，可在推断条件中加入 `type ∈ {Selector, URLTest, Fallback, LoadBalance, Relay}`。不建议预先添加，这属于没有证据的推测性代码。

## 5. 备选方案 B：保留 group 优先，精简实现

如果仍需要“`/group` 成功即为权威”的语义：

1. clash-api 按 §3.2/§3.3 修改，不做任何校验、不加格式开关。
2. 不新增 Feature，不传递 `kind`/`capabilities`，不升级服务。每次刷新与 `/proxies` 并发请求 `/group`；任意失败（含 404）都回退到推断，下一次刷新再试。由于请求并发，clash-rs 上多出的一次 404 不增加刷新延迟，也不需要负缓存。
3. 删除 401/403 特判（F3），以及 `GroupSource`/`GroupFallback`/诊断字段（F4）。降级时 `tracing::debug!(%error, "...")` 一行即可。`ProxySnapshot.groups: Option<IndexMap<..>>` 保留，空的 `IndexMap` 仍表示“权威的空列表”。
4. 删除 `inconsistent_groups` 与 `PartialEq`；`unresolved_members` 也删除。

方案 B 相对 A，多出一个并发 GET 和一个 `Option` 分支，换来对 `all: null` 这一理论情况的覆盖，其余收益为零。

## 6. 待用户决策
