# RPC 权限层 任务卡（P0–P5）

[设计](design.md) r5 的执行清单。

约定：

- 一张卡是一个 PR，一个 PR 做一件事并且能独立构建（`workflow.md` 的提交规则）。
- 只有 P3-3 允许改变授权行为与线上契约，且变化必须逐项列在 P0-2 的变更清单里；其余卡的迁移差异必须为空。
- 主线不改线上方法名与函数名。前端绑定只在 P3-3 变化。
- “验证”列的每一项都要能机械地判断通过与否。
- 改了 guide 所述规则的卡，在同一 PR 里改 guide。
- 开始前按 `workflow.md` 评估是否使用 worktree。须在远程访问栈首次发布前完成（设计 §10 D-1）；在该栈合入前开始时以栈顶为 base 叠加。

依赖：`P0-1 → P0-2 → P1-1 → P2-1 → P3-1 → P3-2 → P3-3 → P4-0 → P4-1 → … → P4-5 → P5-1`，全部串行。P4 各卡的顺序以 P0-2 导出的为准。E 卡单独立项。

### P4-1 至 P4-5 按资源搬迁

每张卡的共同内容：按 P0-2 的映射表，把该资源在两个声明根里的命令、事件、路由移入模块树；加 `expose` 与 `sensitive` 设置；去掉声明上的 `permission`、`http`、`local`；`MAX_LEGACY` 下调。函数名与方法名不变。登记一个现有顶层模块时，其中不得再有 `legacy` 声明。

共同验证：迁移差异为空（推导结果须等于 P3-3 已生效的要求）；三个前端绑定文件无 diff；独立的不变量测试不改期望集合即通过；生成表里该资源的每一行来源不再是 `legacy`。

| 卡   | 资源                 | 特别说明                                                                       |
| ---- | -------------------- | ------------------------------------------------------------------------------ |
| P4-1 | `meta`、`remote`     | 最小的一组，走通全流程                                                         |
| P4-2 | `proxy`              | 延迟测试 `access = write`；healthcheck 归此处                                  |
| P4-3 | `profile`            | 订阅 URL、配置原文、同步日志所在模块标 `sensitive`；代理组的布局与文件夹归此处 |
| P4-4 | `settings`、`system` | 按权限拆分的 patch 命令各归其位；通用存储归 `settings`，其值读取标 `sensitive` |
| P4-5 | `logs`、`traffic`    | 游标与订阅类 `access = read`；原始日志所在模块标 `sensitive`                   |

native 命令（58 条）随所属资源的卡搬迁，位于只对桌面暴露的子模块。
