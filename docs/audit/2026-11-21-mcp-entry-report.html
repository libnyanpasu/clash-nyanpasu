MCP 入口：由应用经 Streamable HTTP 提供，渐进披露，按 agent 授权

2026-11-21 代码基准：9107b62bb（renovate/zbus-6.x；与本地 main 的合并基 3f73c81b1） 设计：Claude（Fable）起草；codex gpt-6.2-astra 独立提案一份、评审三轮；team-lead 自核一轮 设计稿 r9，尚未实施；18 项已裁定，无待裁定
结论：应用在现有的远程访问 HTTP 监听上提供 POST /bridge/mcp（rmcp 3.11.0，无状态）。MCP 调用与 /bridge/rpc 走同一个 registry 与 Authority；凭证是只在这个入口有效的 token；交给 agent 的每个应答先投影（Agent 一档）再按凭证的共享模式交付。不做 OAuth。首版暴露 23 条命令，其中 4 条带敏感标记。没有编译或运行任何代码：四项前置试验（M0）里有两项是硬性条件。

第一部分 · 概览与审查

目标与范围

目标 做法
入口随应用更新 挂在远程访问的 HTTP 监听上，不在 CLI 里
不另建授权路径 同一个 registry、Authority、审计；新的目标 RpcTarget::Mcp
暴露面显式、默认关闭 按命名空间或命令写 expose = [..., mcp]；首版 23 条
agent 逐级发现 四个固定的元工具；目录从生成表推出，入参 schema 由 schemars 派生
每个 agent 一条凭证 只在 MCP 入口有效；缺省只读且只能查询，由服务端约束
交出去的内容受控 先投影（去掉识别性的字段、抹掉凭据），再按共享模式交付、询问或拒绝
有地方管 设置里的“AI 集成”页

不做的

  • OAuth；MCP 征询作为确认；“允许后发送完整版本”。
  • 经 MCP 的事件、流、字节路由；prompts、sampling、roots、tasks、Skills 扩展；输出 schema。
  • 其他调用者（Token、Session、Anonymous）的数据共享规则；取代 C-2 的通用部分。
  • 本地 socket 握手的收窄（留在 #6492）；#5946 的按等级导出脱敏。
  • CLI 里的 MCP 服务器；CLI 写入各 agent 的配置文件。

客户端矩阵（摘要）

客户端 Streamable HTTP 静态请求头 连本机 / 局域网 备注
Claude Code 是 claude mcp add --transport http … --header；.mcp.json 的 headers 是 自带工具延迟加载

Claude Desktop 远程连接器 / claude.ai 远程 HTTPS 有（受限的 beta） 否：请求来自 Anthropic 云端 只写文档：mcp-remote --header（D-8）

OAuth：不需要，不做

  • 规范不要求。“Authorization is OPTIONAL for MCP implementations.” 静态 Bearer 是“不实现 MCP 授权”，偏离的只是一条 SHOULD。
  • 做了也不增加可达的客户端。没有哪个目标客户端只支持 OAuth。
  • 连不上的是 Claude Desktop 的远程连接器与 claude.ai，原因是网络路径（公网 HTTPS 的 443），OAuth 解决不了。
  • 在局域网上反而更差。Claude Code 只把 OAuth 凭证发给 HTTPS 或回环上的 token 端点；CIMD 的 client id 必须是 https；还要有一个授权服务器。
  • 服务端的做法：/bridge/mcp 的 401 带 WWW-Authenticate: Bearer，不带 resource_metadata，不提供 /.well-known/oauth-protected-resource。

规则 内容
双向配对 Mcp 受众的 token 只在 /bridge/mcp 上受理；/bridge/mcp 只受理它。在 /bridge/rpc、事件、流、路由与 /bridge/login 上无效
不泄露 受众不符与凭证无效同为 401；受众相符之后才更新最近使用时间
构造 Principal::Mcp 只能经 AuthContext::mcp 构造；registry 分派前核对“Mcp 当且仅当 Sharing::Policy”

撤销落盘失败 用可区分的结果带出；只对待写出的 id 的再次撤销重写记录
新 CLI 对旧宿主 先确认宿主支持，再核对返回的受众，然后才输出密钥

4. 收窄：Nyanpasu-Max-Role

请求头 有效权限 变更入口
缺省 Grant ∩ viewer 关闭：tools/list 省略 mutate_operation
viewer / operator / admin Grant ∩ 该角色 打开；逐条仍由 Authority 判定

mcp 目标的规则

  1. 顶层模块不得写 mcp；开放的最小单位是二级命名空间或单条命令。
  2. mcp 不受“子集”检查，按最近的显式 expose 生效。
  3. 对最终的行检查：含 mcp 必须含 http、必须声明 privacy、必须是命令、不得是带 sensitive 的变更、声明根不得是 tauri/src/ipc.rs。
  4. 暴露集合由一个夹具钉住，增删都是评审过的变更。

7. 共享模式（⑥）

模式 普通（不带标记） 敏感（带标记） 用在哪
allow_all 全部允许 交付 交付 自己机器上完全信任的 agent
ask_sensitive 敏感内容需询问（默认） 交付 询问 一般情况
ask_all 全部询问 询问 询问 想逐次看 agent 拿走了什么
deny_sensitive 拒绝敏感内容 交付 拒绝 无人值守、无界面的宿主
  • 每条凭证一个模式，随认证取快照；改模式先落盘后生效，只影响之后认证的请求。
  • “交付”放行的是投影后的那一份——模式省掉的是预览，不是脱敏。
  • 错误不经确认：对 Mcp 是固定文案。
  • ask_all 下变更也会被询问，那时变更已经执行；页面与错误消息里写明。
  • 无界面的宿主上两个“询问”的模式等同拒绝。

9. 确认：所有者、适配层、放行与撤销

消息 来自 所有者做什么
reserve 类型化客户端，读取之前 没有呈现端口、撤销订阅已关闭、名额已满：失败。否则铸造 ShareId，登记为 Reading；客户端随后核对凭证，失效则撤回
present 适配层，handler 返回之后 不在 Reading：丢弃文本。超过 1 MiB 或通知失败：Unavailable。否则转 Pending
resolve 桌面的确认命令 不在 Pending：Gone。已到期限：Expired。拒绝：Denied。允许：转 Releasing，由客户端去核对凭证
核对的结果 类型化客户端 有效 → Released（放行点）；否则 Revoked
expire 适配层的计时器 Pending → Expired
请求方离开 名额被丢弃或 abandon Reading → Abandoned，名额不归还；Pending / Releasing：移除
finished 适配层，读取结束 归还名额
撤销 AuthRevocation 广播 该凭证的项 → Revoked。滞后：全部 Revoked，继续；关闭：全部 Revoked，此后 reserve 一律失败 
// nyanpasu-rpc/src/mcp/confirm.rs —— ShareReservation::finish 的全部内容
let Some(payload) = payload.filter(|_| !abandoned) else { shares.finished(&ticket); return ShareOutcome::Unavailable };
let deadline = Instant::now() + SHARE_CONFIRM_LIMIT;                  // 30 秒，单调时钟
shares.present(&ticket, payload, deadline).await;
tokio::select! {
    verdict = ticket.verdict() => return verdict.into(),
    () = tokio::time::sleep_until(deadline) => shares.expire(&ticket),
}
ticket.verdict().await.into()   // 到期之后读的仍是所有者写下的那一个结论
性质 怎样保证
答复不会落到别的项上 ShareId 随机、不复用，与线上的请求 id 无关
期限之后的“允许”不算数 适配层起算绝对期限，所有者在处理答复时比较
结论只有一个 每个名额带一次性的结论接收端；先处理的那个胜出
无关的项不被卡住 所有者不等待别的 actor；两次凭证核对由客户端在其邮箱之外做
同时在读的结果有上界 名额在读取之前占用、读取结束才归还（每凭证 4、全局 16，文本 1 MiB）
放行点 认证所有者对“凭证此刻是否有效”的一次串行答复；之前撤销则不放行，之后的字节收不回
界面随表而动 一项离开列表时调 SharePresenter::changed
取消 读取期间只 abandon；等结论期间丢弃名额。支持的取消方式是断开连接

码（kind = forbidden） 何时

情形 审计的阶段
准入或模式拒绝 Rejected
占不到名额 Admitted → Finished(Failure, NotExecuted)
handler 出错 Admitted → Finished(Failure)
